Branchement Alpha77 sans collision

Deux sessions, 38 leçons, une branche et un jeu de chemins par leçon, un registre central qui n'accorde chaque leçon qu'une fois.

1. Arbre des branches

Chaque leçon part de main sur sa propre branche et y revient par sa propre PR. Aucune branche n'est partagée entre leçons ni entre sessions.

2. Verrou de réservation

Avant d'écrire, un agent réserve sa leçon dans le registre medina/session-registry. Le push y est normal, jamais forcé : de deux réservations simultanées, une seule gagne.

  N -- "non" --> R

3. Pourquoi aucune collision n'est possible

  • Même leçon : le registre n'accorde une mission qu'une fois.
  • Même branche : une branche par leçon, pas de push forcé.
  • Même fichier : chaque mission n'autorise que chapters/<CODE>, glossary/<code>.py, ses images, son reçu et son dossier d'exécution. La garde locale et le contrôle « mission et périmètre » de GitHub refusent tout le reste.
  • Fusion : les chemins sont disjoints, donc les PR fusionnent dans n'importe quel ordre.
  • Jauge : tenue par la seule session A, à partir de l'état GitHub.
