# Outils GitHub et API pour images médicales sous licence ouverte — relevé du 14 octobre 2026

Périmètre : trouver, télécharger, optimiser et insérer des images **réelles** (jamais générées) avec licence et auteur, plus vérification éventuelle de sources. Méthode : lecture seule (README, code principal des candidats sérieux via `raw.githubusercontent.com`, métadonnées via la recherche GitHub) et appels directs aux API publiques sans clé. Aucun code tiers n'a été exécuté ni installé.

Limites du relevé : la recherche GitHub passe par un outil restreint (stars, dates `updated_at`/`pushed_at` du dépôt, pas le détail des derniers commits ; « activité » ci-dessous = date de dernière mise à jour du dépôt). Les dépôts d'agrégation ne sont pas audités ligne à ligne. Aucun skill Claude dédié à Wikimedia Commons n'a été trouvé sur GitHub avec un SKILL.md vérifiable.

## 3. Constats

1. Aucun skill GitHub ne fait mieux qu'un script local de ~100 lignes appelant directement Commons et Openverse : les MCP trouvés sont de petits projets de particuliers (0 à 18 étoiles), dont certains récents ou inactifs, et chacun ajoute l'exécution de paquets npm tiers pour une fonction qui tient dans un appel HTTP.
2. Commons fournit tout ce qu'exige la règle (licence, URL de licence, auteur, source, page de description) dans `extmetadata` ; Openverse aussi.
3. Open-i était hors service lors du test ; Europe PMC remplace l'accès aux figures PMC en CC BY via le texte intégral XML (non testé ici).
4. Les licences NC et ND existent dans les résultats (Europe PMC : « cc by-nc-nd ») : elles sont à rejeter par liste blanche, pas par liste noire.

## 4. Recommandations et procédure minimale

Ne rien installer de tiers. Si Vial l'autorise, créer un petit outil `tools/images_ouvertes.py` en bibliothèque standard (`urllib`, `json`, `hashlib`) ; Pillow n'est nécessaire que pour l'optimisation (à vérifier dans l'environnement).

1. **Recherche** : Commons `action=query&generator=search&gsrnamespace=6&gsrsearch=<termes> filetype:bitmap&prop=imageinfo&iiprop=url|size|mime|extmetadata`, avec `iiurlwidth` pour une miniature. User-Agent nominatif avec contact ; un appel à la fois, pause d'au moins 1 s, `maxlag=5` ; en cas de « too many requests », attendre et ne pas insister.
2. **Liste blanche automatique** sur `LicenseShortName` : CC0, Public domain / PD-*, CC BY (toutes versions), CC BY-SA (toutes versions). Refuser NC, ND, GFDL seul, « fair use », vide ou inconnu. Pour Openverse : `license` dans `cc0`, `pdm`, `by`, `by-sa`. Pour Europe PMC : `license` = « cc0 » ou « cc by », avec contrôle de la légende de chaque figure.
3. **Contrôle humain de l'image** (obligatoire) : ouvrir la page de description, confirmer que la photo est réelle (pas une illustration générée par IA, pas un schéma présenté comme photo), que le diagnostic de la légende correspond au cours, que la personne photographiée n'est pas identifiable sans consentement, et que la licence affichée sur la page est identique à l'API.
4. **Téléchargement** : version redimensionnée (miniature `iiurlwidth` ≈ 800–1200 px) plutôt que l'original ; calcul SHA-256 ; conversion WebP ou JPEG qualité ~80 si Pillow est disponible ; enregistrement sous un dossier d'images du projet avec nom stable.
5. **Manifeste** `images/MANIFEST.json` par image : titre du fichier, URL de description, URL du fichier, auteur (HTML nettoyé), source, licence (nom + URL), date de récupération, SHA-256, cours et leçon concernés.
6. **Insertion HTML** : `<figure><img src alt="description précise" loading="lazy" width height><figcaption>légende pédagogique. Auteur, titre du fichier, licence (lien), source (lien), via Wikimedia Commons.</figcaption></figure>` ; pour CC BY et CC BY-SA, l'attribution est affichée au même endroit que l'image ; pour CC BY-SA, mentionner la licence de l'image sans l'étendre au cours.
7. **Contrôle automatique** avant livraison : toute `<img>` des cours doit figurer au manifeste avec licence de la liste blanche ; échec de la livraison sinon.
8. **Vérification de sources** : utiliser les outils PubMed déjà disponibles dans la session et les sources suisses/européennes de la règle MEDINA ; ne pas ajouter de MCP médical américain (ex. n° 11).

Un skill local `.claude/skills/images-ouvertes/SKILL.md` décrivant cette procédure (modèle : dépôt n° 12) peut être ajouté après validation de Vial ; il n'est pas créé par ce relevé.
